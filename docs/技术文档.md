## 1. 技术选型

### 1.1 技术栈决策表

| 维度 | 选型 | 版本 | 决策理由 |
|---|---|---|---|
| 架构形态 | 静态 SPA（单 HTML + hash 路由） | — | 无后端；导航统一；数据驱动渲染天然契合 |
| 样式 | Tailwind CSS | v4 | 需求指定；v4 采用 CSS-first 配置，无需 JS 配置文件 |
| 脚本 | 原生 ES Module | ES2022 | 零构建、零依赖；项目规模不需要框架 |
| 数据 | 多个 JSON 文件 + `fetch()` | — | 需求指定；改数据不动代码 |
| 模板 | 模板字符串 + 统一转义函数 | — | 避免引入模板引擎；比手写 DOM API 更可读 |
| 状态 | 页面模块内局部状态 + URL hash 参数 | — | 只有食物页有多条件状态，无需全局状态库 |
| 图表 | 内联 SVG / 纯 CSS | — | 只有堆叠条一种图，引第三方库不划算 |
| 构建 | 无构建（开发）/ Tailwind CLI（交付） | — | 见 §1.3 |
| 包管理 | 仅 devDependency 一个 tailwind | — | 运行时不加载任何第三方 JS |

### 1.2 为什么不用框架（React / Vue）

1. 全站是**只读内容呈现**，没有复杂状态流转。唯一有状态的是食物页的搜索/筛选/排序/对比，用 30 行原生代码足够。
2. 无框架 = 无 node_modules 运行时依赖 = 双击 `start.bat` 就能跑，符合「无后端、方便后期修改」的原始诉求。
3. 内容全部在 JSON 里，页面逻辑极薄。引入框架的收益（组件复用、响应式更新）在此处几乎用不到。

**唯一代价**：需要手写 `escapeHtml` 和事件委托。已在 §9.3 规范。

### 1.3 Tailwind 引入方式

**已采用「CLI 预编译为静态 CSS」方案**（见 §0 实现说明）：

| 方案 | 状态 | 说明 |
|---|---|---|
| CLI 预编译 → `assets/css/tailwind.css` | **采用** | 30 KB 静态文件，运行时零依赖、可离线、无首屏闪烁 |
| 浏览器运行时编译（`@tailwindcss/browser`） | 备选 | 需要联网、首屏有编译闪烁、控制台有生产环境警告；仅作为临时调试手段保留在 `index.html` 的注释中 |

`src/input.css`：

```css
@import "tailwindcss";

@source "../index.html";
@source "../assets/js/**/*.js";

@theme {
  --color-brand-50:  #f0fdf4;
  --color-brand-100: #dcfce7;
  --color-brand-500: #22c55e;
  --color-brand-600: #16a34a;
  --color-brand-700: #15803d;
  --font-sans: "PingFang SC", "Microsoft YaHei", "Hiragino Sans GB", system-ui, sans-serif;
}

.ui-card { @apply rounded-xl border border-gray-200 bg-white p-5; }
/* …其余组件类见文件 */
```

> `@source` 告诉 Tailwind 去哪里扫描类名。JS 文件必须被扫描到，否则组件里拼出的类名不会生成。

### 1.4 浏览器兼容目标

| 浏览器 | 最低版本 | 依赖特性 |
|---|---|---|
| Chrome / Edge | 90+ | ES Module、可选链、`<dialog>` |
| Firefox | 90+ | 同上 |
| Safari | 15+ | `<dialog>` 支持较晚，需注意 |
| 移动端 | iOS 15+ / Android Chrome 90+ | 同上 |

**降级策略**：`<dialog>` 不可用时回退为固定定位遮罩层（`@supports not (dialog::backdrop)` 检测）。

## 2. 系统架构

### 2.1 分层结构

```
┌─────────────────────────────────────────────┐
│  index.html        唯一入口，含导航壳与挂载点   │
└─────────────────────────────────────────────┘
                    │
        ┌───────────┴───────────┐
        ▼                       ▼
┌───────────────┐      ┌────────────────────┐
│  core/router  │      │  core/store        │
│  hash 路由     │      │  JSON 加载与缓存    │
└───────┬───────┘      └─────────┬──────────┘
        │                        │
        ▼                        │
┌───────────────────────────────┐│
│  pages/*      页面模块         │◄┘
│  负责：加载数据、拼装 HTML      │
└───────────┬───────────────────┘
            ▼
┌───────────────────────────────┐
│  components/registry + 7 个组件 │
│  按 section.type 渲染内容块     │
└───────────────┬───────────────┘
                ▼
        ┌───────────────┐
        │  data/*.json  │
        └───────────────┘
```

### 2.2 一次页面渲染的完整数据流

```
1. 用户点击导航 → hash 变化 → hashchange 事件
2. router 匹配路由 → 得到页面模块 pages/carbs.js
3. router 调用 页面.render(store)
4. 页面内 await store.load('carbs') → fetch('data/carbs.json') → 缓存
5. 页面把 JSON 的 sections[] 逐个交给 registry.renderSection()
6. 每个 section 由对应组件生成 HTML 字符串
7. 页面拼装完整 HTML → 一次性写入 #app 的 innerHTML
8. 页面.mount(root, data) 绑定事件（委托）
9. router 更新导航高亮 + 滚动到顶部 + 设置 document.title
```

**关键设计：字符串拼装 + 单次 innerHTML 写入**，而不是逐节点 append。100 条食物卡片约 1 次 DOM 操作，比循环 append 快一个数量级。

### 2.3 内容与代码的边界（最重要的约定）

| 归 JSON | 归代码 |
|---|---|
| 所有科普文案、标题、导语 | 布局结构与 Tailwind 类名 |
| 所有表格的行列数据 | 表格的斑马纹、边框、响应式滚动 |
| 所有举例、食物清单 | 卡片的网格列数、圆角、阴影 |
| 误区 myth/fact 文案 | 误区卡的红绿配色 |
| 榜单条目与排序 | 排名徽标的样式 |

> **判定标准**：如果删掉这条内容，页面结构不变 → 放 JSON。如果删掉后布局塌了 → 才考虑放代码。
> 遵守此约定后，「加 20 条食物」= 只改 `foods.json`。

### 4.1 路由表

| hash | 页面模块 | 数据文件 | document.title |
|---|---|---|---|
| `#/` 或空 | `home.js` | meta.json | 营养学知识库 |
| `#/overview` | `overview.js` | nutrients.json | 营养素总览 · 营养学知识库 |
| `#/carbs` | `carbs.js` | carbs.json | 碳水化合物 · 营养学知识库 |
| `#/protein` | `protein.js` | protein.json | 蛋白质 · 营养学知识库 |
| `#/fat` | `fat.js` | fat.json | 脂肪 · 营养学知识库 |
| `#/foods` | `foods.js` | foods.json + meta.json | 食物营养图谱 · 营养学知识库 |
| `#/quick` | `quick.js` | rankings.json | 速查表 · 营养学知识库 |
| `#/faq` | `faq.js` | faq.json | 常见疑问 · 营养学知识库 |
| 其他 | 404 视图 | — | 页面未找到 |

### 4.2 hash 参数（仅食物页使用）

用于让筛选状态可分享、可回退：

```
#/foods?q=燕麦&tags=slow-carb,high-fiber&sort=protein_g:desc
```

| 参数 | 含义 | 默认 |
|---|---|---|
| `q` | 搜索关键词 | 空 |
| `tags` | 标签 id，逗号分隔（AND 逻辑） | 空 |
| `cat` | 分类 id | 全部 |
| `sort` | `字段:asc\|desc` | `name:asc` |

**实现约定**：
- 状态变更 → 写入 hash（用 `history.replaceState` 避免污染历史栈）
- hash 变化 → 重读参数 → 重新渲染列表（只重渲染列表容器，不整页重渲）
- 用 `replaceState` 而非 `pushState`，避免每次输入一个字符就多一条历史记录

### 4.3 路由实现要点

```js
// core/router.js
const routes = new Map();

export function register(path, page) {
  routes.set(path, page);
}

export function resolve() {
  const raw = location.hash.replace(/^#/, '') || '/';
  const [path, queryStr] = raw.split('?');
  const query = Object.fromEntries(new URLSearchParams(queryStr || ''));
  const page = routes.get(path) || routes.get('404');
  return { page, query, path };
}

export async function start(app, store) {
  const run = async () => {
    const { page, query, path } = resolve();
    const root = document.getElementById('app');

    // 1. 更新导航高亮（按 path 前缀匹配，foods 详情也高亮 foods）
    document.querySelectorAll('[data-nav]').forEach(a => {
      const active = a.dataset.nav === path;
      a.classList.toggle('text-brand-600', active);
      a.classList.toggle('font-medium', active);
      a.classList.toggle('text-gray-600', !active);
      active ? a.setAttribute('aria-current', 'page') : a.removeAttribute('aria-current');
    });

    // 2. 渲染页面
    root.setAttribute('aria-busy', 'true');
    try {
      const { html, onMount } = await page.render(store, query);
      root.innerHTML = html;
      document.title = page.title + ' · 营养学知识库';
      onMount?.(root, store, query);
      // 3. 内容页自动生成锚点目录（见 §6.5）
      buildToc(root);
    } catch (err) {
      root.innerHTML = renderError(err);
    } finally {
      root.setAttribute('aria-busy', 'false');
    }
    window.scrollTo(0, 0);
  };

  window.addEventListener('hashchange', run);
  await run();
}
```

**404 视图**：静态 HTML，含「返回首页」按钮和全部页面链接列表（提升可发现性）。

## 5. 数据层规范

### 5.1 通用约定

| 项 | 规范 |
|---|---|
| 编码 | UTF-8 **无 BOM** |
| 缩进 | 2 空格 |
| 字段命名 | camelCase（`energy_kcal` 这类单位后缀也用 snake 连接在 camelCase 键内，保持一致） |
| 字符串引号 | 双引号 |
| 数值 | 不带引号；未知值用 `null`，**不用** `-1` 或 `"N/A"` 表示缺失 |
| 布尔 | `true` / `false` |
| 版本字段 | 每个文件顶层含 `"version"` 与 `"updatedAt"` |
| 单位 | 统一 `per: 100, unit: "g"`（每 100 克），能量用 kcal |

### 5.2 文件清单

| 文件 | 顶层结构 | 实测体积 |
|---|---|---|
| `meta.json` | `site` / `nav` / `home` / `sources` / `disclaimer` | 3.3 KB |
| `nutrients.json` | `intro` / `sections[]` / `myths[]` | 6.3 KB |
| `carbs.json` | `intro` / `sections[]` / `myths[]` | 11.6 KB |
| `protein.json` | `intro` / `sections[]` / `myths[]` | 13.8 KB |
| `fat.json` | `intro` / `sections[]` / `myths[]` | 11.3 KB |
| `foods.json` | `categories[]` / `tags[]` / `fields[]` / `items[]` | 57.6 KB |
| `rankings.json` | `intro` / `sections[]` | 8.0 KB |
| `faq.json` | `items[]` | 8.3 KB |
| **合计** | | **约 120 KB** |

> 120 KB 未压缩、gzip 后约 33 KB（JSON 压缩率很高）。**结论：全量一次性加载完全可接受，不需要分页、懒加载或索引优化。**

### 5.3 核心 Schema

#### 5.3.1 通用 section 对象

所有内容型 JSON 的 `sections[]` 共享同一外层结构，由 `type` 决定内部字段：

```json
{
  "id": "refined-vs-slow",
  "title": "精制碳水 vs 慢碳",
  "lead": "同样叫碳水，血糖反应可能差 3 倍。",
  "type": "compare",
  "highlight": true,
  "collapsed": false,
  "...各 type 专属字段": "..."
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | 是 | 页面内锚点 id，须全站唯一 |
| `title` | string | 是 | 章节标题（渲染为 h2） |
| `lead` | string | 否 | 标题下一句话导语 |
| `type` | string | 是 | 渲染组件类型，见 §6.4 |
| `highlight` | boolean | 否 | 是否加视觉强调（主色左边框 + 浅底） |
| `collapsed` | boolean | 否 | 是否默认折叠（长表格用） |

#### 5.3.2 各 type 的专属字段

**type: `cards`**

```json
{
  "type": "cards",
  "columns": 3,
  "items": [
    {
      "title": "碳水化合物",
      "badge": "产能 4 kcal/g",
      "icon": "carb",
      "points": ["主要供能物质", "分单糖 / 双糖 / 多糖"],
      "accent": "green"
    }
  ]
}
```
字段：`columns`(2\|3\|4)、`items[].{title, badge, icon, points[], accent}`、`accent ∈ {green, red, blue, amber, gray}`。

**type: `table`**

```json
{
  "type": "table",
  "columns": [
    { "key": "type", "label": "类别" },
    { "key": "makeup", "label": "组成" },
    { "key": "examples", "label": "代表食物", "align": "left" }
  ],
  "rows": [
    { "type": "单糖", "makeup": "1 个糖分子", "examples": "葡萄糖、果糖、半乳糖" }
  ],
  "footnote": "数据来源：中国食物成分表（第6版）"
}
```
`rows[]` 的键必须与 `columns[].key` 对应。`align ∈ {left, center, right}` 默认 left。

`columns[].width` 可选，传百分比字符串（如 `"34%"`），用于把长内容列撑开。只设需要的那一列即可，其余列交给浏览器自适应。典型场景：某列是多个词用「、」连接的长串（如 9 个氨基酸名），不设宽度会被压到每行只放一个词。

**type: `compare`**（左右对照，本站核心展示形态）

```json
{
  "type": "compare",
  "left": {
    "title": "精制碳水（快碳）",
    "accent": "red",
    "points": ["高 GI，血糖陡升陡降", "纤维几乎为零", "饱腹感差"],
    "examples": ["白米饭", "白馒头", "白面包", "含糖饮料"]
  },
  "right": {
    "title": "慢碳（复合碳水）",
    "accent": "green",
    "points": ["低 GI，供能平缓", "纤维丰富", "饱腹感强"],
    "examples": ["燕麦", "糙米", "藜麦", "红薯"]
```

### 5.4 加载与缓存策略

```js
// core/store.js
const cache = new Map();

export function createStore(basePath = 'data/') {
  async function load(name) {
    if (cache.has(name)) return cache.get(name);
    const url = basePath + name + '.json';
    const res = await fetch(url, { cache: 'no-cache' });
    if (!res.ok) {
      throw new Error(`加载 ${url} 失败：HTTP ${res.status}`);
    }
    // fetch().json() 会校验 Content-Type，服务器必须返回 application/json
    const data = await res.json();
    cache.set(name, data);
    return data;
  }

  async function loadMany(names) {
    const list = await Promise.all(names.map(load));
    return Object.fromEntries(names.map((n, i) => [n, list[i]]));
  }

  return { load, loadMany, clear: () => cache.clear() };
}
```

| 策略 | 取值 | 理由 |
|---|---|---|
| 缓存位置 | 内存 `Map` | 会话内不重复请求；`clear()` 供开发调试 |
| HTTP 缓存 | `cache: 'no-cache'` | 强制每次校验，避免改 JSON 后看到旧内容 |
| 加载时机 | 页面级按需 | 进碳水页只加载 `carbs.json`；首页只加载 `meta.json` |
| 并发 | `Promise.all` | 食物页需 `foods` + `meta`，并行加载 |
| 预加载 | 不做 | 数据量小，收益低 |

### 5.5 错误处理

| 场景 | 表现 |
|---|---|
| JSON 404 | 页面区显示错误卡：「数据文件未找到：data/carbs.json」，附「重试」按钮 |
| JSON 语法错误 | 同上，错误信息中带上 `err.message` |
| **`file://` 协议** | 特殊提示卡（这是最高频的错误，见 §13.1） |
| 单条数据字段缺失 | 不抛错；渲染时用 `format.js` 的 `dash()` 显示「—」，并在控制台 `console.warn` |
| 未知 `section.type` | 渲染一个黄底提示块「未知组件类型：xxx」，不中断整页渲染 |

**关键原则：单条数据有问题不能让整页白屏。** 组件层对每个字段做防御式读取，`fetch` 失败才降级到整页错误视图。

## 6. 渲染引擎与组件规范

### 6.1 组件契约（唯一接口）

```js
/**
 * @param {object} section - JSON 中的 section 对象，含 type 与专属字段
 * @param {object} ctx - { store, meta } 只读上下文
 * @returns {string} HTML 字符串
 */
export default function render(section, ctx) {}
```

**三条约束：**
1. **纯函数**：同样输入必须同样输出，不发请求、不读全局变量。
2. **返回字符串**：不直接操作 DOM，不做 `appendChild`。
3. **可空安全**：任何可选字段缺失时优雅降级，不抛异常。

### 6.2 组件注册表

```js
// components/registry.js
import table from './table.js';
import compare from './compare.js';
import cards from './cards.js';
import giTable from './giTable.js';
import stackedBar from './stackedBar.js';
import list from './list.js';
import ranking from './ranking.js';

const registry = {
  table, compare, cards,
  'gi-table': giTable,
  'stacked-bar': stackedBar,
  list, ranking
};

export function renderSection(section, ctx) {
  const fn = registry[section.type];
  if (!fn) {
    console.warn(`[registry] 未知组件类型: ${section.type}`);
    return `<div class="rounded-lg border border-amber-300 bg-amber-50 p-4 text-sm text-amber-800">
      未知组件类型：${esc(section.type)}</div>`;
  }
  return `<section id="${esc(section.id)}" class="scroll-mt-20 ${section.highlight ? 'border-l-4 border-brand-500 pl-5' : ''}">
    ${fn(section, ctx)}
  </section>`;
}

/** 页面统一入口：把 sections[] 渲染成 HTML */
export function renderSections(sections = [], ctx) {
  return sections.map(s => renderSection(s, ctx)).join('');
}
```

> **扩展方式**：新增展示形态 = 新建组件文件 + 在 registry 加一行 + 在 JSON 里用新 `type`。不改任何页面代码。

### 6.3 七个组件的 DOM 结构与类名规范

统一使用以下 Tailwind 类基线：

| 元素 | 类名基线 |
|---|---|
| 章节外壳 | `mb-12` |
| 章节 h2 | `text-xl font-semibold text-gray-900 mb-2`（**唯一允许 `font-semibold` 的位置**） |
| 章节导语 | `text-sm text-gray-500 mb-5` |
| 卡片 | `bg-white rounded-xl border border-gray-200 p-5` |
| 表格 | `w-full text-sm border-collapse` + 外层 `overflow-x-auto rounded-xl border border-gray-200` |
| 表头 | `bg-gray-50 text-gray-500 text-xs font-medium` |
| 单元格 | `px-4 py-3 border-b border-gray-100` |

**表格换行规则（重要）**

`.ui-td` / `.ui-th` 统一用 `word-break: keep-all` + `overflow-wrap: break-word`：

- `keep-all` 禁止在 CJK 字符之间断行，中文只在标点、空格处换行。不加的话浏览器会在任意字符间断，出现「麦芽 / 糖」「微甜或不 / 甜」这类拆词
- `break-word` 作为兜底，遇到超长且无断点的字符串（长英文单词、URL）时仍允许强制断开
- 两者的副作用是列宽会被内容撑开，超出容器时由表格外层的 `overflow-x-auto` 兜住，退化为横向滚动而不是挤压变形
- 表头第一列与 `table` 组件的第一列额外加 `whitespace-nowrap`。原因：表格 auto layout 会把宽度优先分给长内容列，第一列常被压到不足两个字宽，把「单糖」这种短词挤成竖排
| 徽标 | `inline-flex items-center rounded-md px-2 py-0.5 text-xs font-medium` |

**accent 色映射表**（数据里的 `accent` → 实际类名）：

|---|---|---|---|

| `red` | `bg-red-50` | `text-red-700` | `border-red-200` |
| `blue` | `bg-blue-50` | `text-blue-700` | `border-blue-200` |
| `amber` | `bg-amber-50` | `text-amber-700` | `border-amber-200` |

### 6.5 上一页/下一页

在 `app.js` 中由 `meta.nav` 顺序推导，页面无需自己维护：

```js
function renderPager(currentId) {
  const nav = meta.nav;
  const i = nav.findIndex(n => n.id === currentId);
  const prev = nav[i - 1], next = nav[i + 1];
  return `<nav class="mt-12 flex justify-between border-t border-gray-200 pt-6" aria-label="章节导航">
    ${prev ? `<a href="#${prev.path}" class="text-sm text-gray-500 hover:text-brand-600">← ${esc(prev.label)}</a>` : '<span></span>'}
    ${next ? `<a href="#${next.path}" class="text-sm text-gray-500 hover:text-brand-600">${esc(next.label)} →</a>` : '<span></span>'}
  </nav>`;
}
```

## 8. 交互实现细节

### 8.1 食物列表的状态模型

食物页全部状态收敛到一个对象，避免散落：

```js
const state = {
  q: '',
  tags: new Set(),
  cat: '',
  sort: { key: 'name', dir: 'asc' }
};
```

**单向数据流**：`用户操作 → 改 state → 写 hash → 重渲染列表 → 更新计数`

### 8.2 搜索

```js
function buildHaystack(item, catMap, tagMap) {
  return [
    item.name,
    ...(item.aliases || []),
    catMap.get(item.category) || '',
    item.subCategory || '',
    ...(item.tags || []).map(t => tagMap.get(t) || '')
  ].join(' ').toLowerCase();
}

function matchQuery(item, q) {
  if (!q) return true;
  return buildHaystack(item).includes(q.trim().toLowerCase());
}
```

- 匹配范围：**名称 + 别名 + 分类名 + 子分类 + 标签名**（所以搜「慢碳」能出所有慢碳食物）
- 大小写不敏感
- **不做拼音**（v1）：需要的话在数据里加 `aliases: ["tudou"]`，成本最低
- 防抖 200ms：输入停止后再过滤并重渲染
- 输入框 `type="search"`，支持浏览器原生清除按钮

### 8.3 筛选

- 多标签 **AND** 逻辑：`selected.every(t => item.tags.includes(t))`
- 分类筛选为单选（`cat` 为空表示全部）
- 已选条件以可点击移除的徽标展示在输入框下方
- 实时显示「共 N 条 / 已筛选 M 条」

### 8.4 排序

```js
function sortItems(items, { key, dir }) {
  const mul = dir === 'desc' ? -1 : 1;
  return [...items].sort((a, b) => {
    const va = key === 'name' ? a.name : a.nutrition?.[key] ?? a[key];
    const vb = key === 'name' ? b.name : b.nutrition?.[key] ?? b[key];
    // null 始终排最后，无论升降序
    if (va == null && vb == null) return 0;
    if (va == null) return 1;
    if (vb == null) return -1;
    if (typeof va === 'string') return mul * va.localeCompare(vb, 'zh-Hans-CN');
    return mul * (va - vb);
  });
}
```

> **`null` 永远排最后**，这是数据表排序的关键细节：不这样的话，按「蛋白质」降序时，没填蛋白数据的食物会莫名排到第一。

### 8.5 对比功能

- 最多选 2 项；已选 2 项时，再点第三个 → toast 提示「最多对比 2 项，已替换最早的选择」，不静默失败
- 对比视图用 `<table>` 渲染，**每个指标一行**，两列数据，差值 ≥20% 的一侧加 `bg-brand-50` 高亮
- 对比表包含：热量、蛋白质、脂肪、碳水、纤维、GI，以及分类标签差异
- 用 `<dialog>` 承载对比结果，`showModal()` 打开，ESC 关闭

```js
function diffClass(a, b, key) {
  if (a == null || b == null || a === 0 && b === 0) return ['', ''];
  const base = Math.max(Math.abs(a), Math.abs(b));
  const rel = Math.abs(a - b) / base;
  if (rel < 0.2) return ['', ''];
  return a > b ? ['bg-brand-50', ''] : ['', 'bg-brand-50'];  // 高亮更优的一侧
}
```
> 注意语义：热量高不一定「更优」，所以高亮只表示**差异显著**，不表示优劣。文案上统一为「差异较大」，避免误导。

### 8.6 事件绑定：统一用委托

列表项是动态渲染的，逐项 `addEventListener` 会随重渲染泄漏。**全部事件绑在容器上做委托**：

```js
// pages/foods.js 的 onMount
export function onMount(root, store) {
  const list = root.querySelector('#food-list');

  // 事件委托：一次绑定，覆盖所有重渲染
  list.addEventListener('click', (e) => {
    const card = e.target.closest('[data-food-id]');
    if (!card) return;
    if (e.target.closest('[data-action="compare"]')) {
      toggleCompare(card.dataset.foodId);
    } else {
      openDetail(card.dataset.foodId);
    }
  });

  const input = root.querySelector('#food-search');
  input.addEventListener('input', debounce(() => {
    state.q = input.value;
    syncHash();
    renderListOnly();
  }, 200));
}
```

**性能约定**：筛选/排序时只重渲染列表容器（`#food-list`）和计数文本，不整页重渲染。搜索框保持焦点不丢失。

> 如果整页重渲染，输入框会失焦，用户打不了第二个字 —— 这是纯字符串渲染方案最容易踩的坑。

### 8.7 详情弹窗

用原生 `<dialog>`：

```html
<dialog id="food-detail" class="rounded-2xl p-0 w-[min(92vw,36rem)] backdrop:bg-black/40">
  <div class="p-6">…</div>
</dialog>
```

- 打开：`dialog.showModal()`；关闭：`dialog.close()` 或 ESC
- 内容每次重写 `innerHTML`，避免残留旧数据
- 降级：`@supports not selector(dialog::backdrop)` 时改用 `div.fixed.inset-0.z-50`

### 9.3 XSS 防护与转义

所有插入 HTML 的动态内容必须经过 `esc()`：

```js
// core/dom.js
const ESC_MAP = { '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' };

export function esc(v) {
  if (v == null) return '';
  return String(v).replace(/[&<>"']/g, c => ESC_MAP[c]);
}

/** 显示缺失值的占位符 */
export function dash(v, suffix = '') {
  return v == null ? '<span class="text-gray-300">—</span>' : esc(v) + suffix;
}
```

**规则**：模板字符串里凡是 `${}` 插入 JSON 数据的位置，**一律包 `esc()`**。唯一例外是已知安全的数值经 `Number()` 转换后拼接。

### 11.2 `tools/serve.js`（零依赖回退方案）

关键点：**必须为 `.json` 返回 `Content-Type: application/json`**，否则 `res.json()` 会抛错。

```js
import { createServer } from 'node:http';
import { readFile } from 'node:fs/promises';
import { extname, join, normalize } from 'node:path';

const root = process.cwd();
const port = Number(process.argv[2]) || 8080;

const MIME = {
  '.html': 'text/html; charset=utf-8',
  '.js':   'text/javascript; charset=utf-8',
  '.css':  'text/css; charset=utf-8',
  '.json': 'application/json; charset=utf-8',
  '.svg':  'image/svg+xml',
  '.png':  'image/png',
  '.ico':  'image/x-icon'
};

createServer(async (req, res) => {
  try {
    let p = decodeURIComponent(new URL(req.url, 'http://x').pathname);
    if (p === '/') p = '/index.html';
    const file = normalize(join(root, p));
    if (!file.startsWith(root)) { res.writeHead(403).end('Forbidden'); return; }
    const body = await readFile(file);
    res.writeHead(200, {
      'Content-Type': MIME[extname(file)] || 'application/octet-stream',
      'Cache-Control': 'no-cache'
    });
    res.end(body);
  } catch {
    res.writeHead(404, { 'Content-Type': 'text/plain; charset=utf-8' }).end('404 Not Found');
  }
}).listen(port, () => console.log(`http://localhost:${port}`));
```

### 12.1 GitHub Pages 的两个坑

**坑一：Jekyll 会忽略下划线开头的文件（已修复）**

GitHub Pages 的「Deploy from a branch」模式默认先跑一遍 Jekyll 构建。Jekyll 有一条硬约定：**以下划线 `_` 开头的文件和目录不参与输出**（它自己用 `_posts`、`_layouts` 这类命名）。

项目最初有两个这样的文件：

```
assets/js/components/_shared.js    ← 被 7 个组件 import
assets/js/pages/_content.js        ← 被 5 个页面 import
```

在 Pages 上它们会 404，导致 ESM `import` 失败，表现为**部分页面白屏**：首页和 FAQ 正常（不依赖这两个文件），其余 6 个页面打不开。本地 `start.bat` 完全正常，所以这个问题只在部署后才暴露。

已做两层修复：

1. 重命名为 `parts.js` 与 `contentPage.js`，彻底消除下划线命名
2. 仓库根目录添加 `.nojekyll` 空文件，让 Pages 跳过 Jekyll 处理

> `.nojekyll` 还顺带解决了另一个问题：不加它的话，`docs/*.md` 会被 Jekyll 渲染成 HTML，而 Markdown 里带 `{ }` 的代码示例可能让构建直接失败。

**坑二：部署目录的选择**

Pages 的 Source 有三条路，本项目推荐第 1 条：

| 方案 | 设置 | 说明 |
|---|---|---|
| **1. 仓库根目录**（推荐） | Source = `Deploy from a branch` → main → `/ (root)` | 把 `nutrition-site/` 里的内容直接作为仓库根推上去 |
| 2. `/docs` 目录 | Source = main → `/docs` | 需要把网站挪进 `docs/`，但那里已经放了需求与技术文档，会混淆 |
| 3. GitHub Actions | Source = `GitHub Actions` | 需要额外写 workflow，纯静态站没必要 |

**如果整个 `nutrition-site` 文件夹被塞进了仓库的子目录**，Pages 会从仓库根提供服务，访问根路径就看不到站点。这种情况要么调整仓库结构，要么在 Pages 设置里指定正确的目录。

> 另外：GitHub Free 账号的**私有仓库不能启用 Pages**，必须是公开仓库（或升级付费计划）。

### 12.2 hash 路由的部署优势

本站用 hash 路由（`#/carbs`），不是 History API 路由。这在部署时省掉了一整类麻烦：

- 不需要配置服务端重写规则
- 不需要 404.html 兜底
- 刷新任意页面、直接分享带参数的链接（`#/foods?q=燕麦&tags=slow-carb`）都能正常打开
- 部署到任意子路径（`username.github.io/repo/`）都不用改一行代码，因为所有资源路径都是相对的

### 12.3 公开部署时的信息暴露

Pages 会把仓库里**所有**文件都发布出去，包括 `tools/`、`src/`、`docs/`。这些不是秘密（前端源码本来就完全公开，见 §13.6），但如果你不希望访客能直接访问 `tools/serve.js` 或 `docs/技术文档.md`，有两条路：

- 保持现状 —— 这些是开发者文件，被看到也无实际风险
- 改用 GitHub Actions 部署，只挑选 `index.html` / `assets/` / `data/` 上传 —— 代价是多维护一个 workflow

## 13. 风险与备选方案

### 13.1 `file://` 下 fetch 被拦截（最高频问题）

| 项 | 说明 |
|---|---|
| 现象 | 控制台报 `Access to fetch at 'file:///.../data/meta.json' from origin 'null' has been blocked by CORS policy` |
| 根因 | 浏览器对 `file://` 协议的 XHR/fetch 一律拒绝（同源策略，origin 为 `null`） |
| 方案 A（采用） | 提供 `start.bat` + `tools/serve.js`，走 `http://localhost` |
| 方案 B（否决） | 把 JSON 改成 `.js` 文件用 `export default {...}` 引入 —— 会失去「纯 JSON，随手可改」的核心优势 |
| 方案 C（否决） | 内联进 HTML —— 数据与结构耦合，违背 §2.3 边界 |
| 兜底 | 若用户仍直接双击打开，页面渲染一个明确的提示卡，写清「请运行 start.bat」，而不是空白页 |

### 13.2 Tailwind 类名动态拼接失效

- **风险**：`class="bg-${accent}-50"` 这种写法在构建版中不会生成对应 CSS
- **规避**：accent → 类名的映射全部写成完整字面量对象（§6.3 映射表），禁止运行时拼字符串

### 13.3 Tailwind v4 与 v3 语法差异

- v4 用 `@theme` 指令配令牌，v3 用 `tailwind.config.js`
- v4 CDN 是 `@tailwindcss/browser`，v3 是 `cdn.tailwindcss.com`
- **规避**：文档统一按 v4 写；若构建环境受限需降级 v3，只改 `src/input.css` 和 `index.html` 一处，业务类名基本兼容（`bg-brand-50` 等自定义色在 v3 的 config 里同名声明即可）

### 13.4 数据准确性

- **风险**：食物成分数值随手写会失去可信度
- **规避**：每条食物带 `source` 字段；若某数值不确定，填 `null` 而不是估一个数；页面页脚统一展示 `meta.sources`

### 13.5 内容体量膨胀后单文件难维护

- **风险**：`foods.json` 如果涨到 500+ 条，单文件编辑体验差
- **预案**：`foods.json` 的 `items[]` 按分类拆为 `foods/grain.json` 等，`store.load('foods/grain')` 后合并。**v1 不做**（100 条不需要），但 `store.js` 的 `basePath + name + '.json'` 设计已支持子目录路径，届时无需改核心代码

### 13.6 前端源码与数据的公开性（重要认知）

**上线后，访客可以完整获取本站的全部 HTML、CSS、JS 与 JSON。** 这不是配置疏漏，而是 Web 的工作原理：文件必须先下发到访客的机器上才能被渲染。

获取方式（从易到难）：

1. DevTools → Network → 刷新页面 → 全部请求可见，右键可逐个下载或整包导出
2. DevTools → Sources → 直接看到全部 JS 源文件
3. Console 一行命令：`await (await fetch('/data/foods.json')).json()`
4. 甚至不用 DevTools，浏览器「网页另存为」就能拿到大部分资源

**任何前端防护手段都只能提高成本，不能阻止**：

| 手段 | 实际效果 |
|---|---|
| 禁用右键 / 屏蔽 F12 | 无效，且伤害正常用户体验 |
| JS 混淆压缩 | 提高代码阅读成本，但功能照跑、数据照拿（JSON 仍以明文出现在 Network 里） |
| JSON 加密 + 前端解密 | 无效，解密密钥同样在前端 |
| 后端 API + 鉴权限流 | 唯一能真正提高抓取成本的方式，但代价是放弃「纯静态、改 JSON 即改站」的全部优势 |

**本项目的取舍**：内容主体是公开的学术知识（食物成分表、GI 值），原创价值在于整理、分类框架与文案表述。因此选择保持纯前端架构，不为了保护而牺牲可维护性。

真正值得做的是**可追溯**而非**防复制**：

1. 页脚保留数据来源标注与免责声明（已在 `meta.json` 中配置）
2. 如需主张权利，可补充版权声明 —— 注意事实性数据本身不受著作权保护，受保护的是文案表述、分类结构与编排方式（汇编作品）
3. 可考虑在 JSON 中埋入有辨识度的原创表述作为水印，被抄时便于举证
4. 认清护城河：抄走 JSON 的人得到的只是一份**快照**，拿不到后续的修正与更新

### 15.3 为什么加了两个额外工具

原生 ESM + 字符串渲染的组合有两个盲区，浏览器只在运行时才报错，且往往表现为白屏，排查成本高。因此补了两个静态检查脚本：

**`tools/check-imports.js`** —— 浏览器 ESM 要求 import 路径**必须带 `.js` 后缀**，漏写只会得到 404 和控制台报错。该脚本扫描全部模块，检查：路径指向的文件是否存在、是否带 `.js` 后缀、具名导入的名字在目标文件里是否真的导出。

**`tools/smoke.mjs`** —— 利用一个关键性质：所有页面的 `render()` 都是**纯函数**（只依赖传入的 store，不碰 DOM），因此可以直接在 Node 里执行，不需要浏览器。检查输出 HTML 中是否出现：`undefined`、`NaN`、`[object Object]`、未注册组件提示、页内链接是否指向真实路由。

这两项检查覆盖了本项目 90% 的「改完就白屏」类故障。约定：**每次改完数据或组件后跑一次 `npm run check && node tools/smoke.mjs`**。

```js
const ESC_MAP = { '&': '&amp;', '<': '&lt;', '>': '&gt;', '"': '&quot;', "'": '&#39;' };

export function esc(v) {
  if (v == null) return '';
  return String(v).replace(/[&<>"']/g, c => ESC_MAP[c]);
}

export function dash(v, suffix = '') {
  return v == null
    ? '<span class="text-gray-300">—</span>'
    : esc(v) + esc(suffix);
}

export function num(v, decimals = 1, suffix = '') {
  return v == null
    ? '<span class="text-gray-300">—</span>'
    : `<span class="tabular-nums">${Number(v).toFixed(decimals)}</span>${esc(suffix)}`;
}

export function debounce(fn, wait = 200) {
  let t;
  return (...args) => { clearTimeout(t); t = setTimeout(() => fn(...args), wait); };
}

const ACCENTS = {
  green: { bg: 'bg-brand-50', text: 'text-brand-700', border: 'border-brand-200' },
  red:   { bg: 'bg-red-50',   text: 'text-red-700',   border: 'border-red-200' },
  blue:  { bg: 'bg-blue-50',  text: 'text-blue-700',  border: 'border-blue-200' },
  amber: { bg: 'bg-amber-50', text: 'text-amber-700', border: 'border-amber-200' },
  gray:  { bg: 'bg-gray-50',  text: 'text-gray-600',  border: 'border-gray-200' }
};

/** accent 必须映射为完整字面量类名，禁止运行时拼接（见技术文档 §13.2） */
export function accentOf(name = 'gray') {
  return ACCENTS[name] || ACCENTS.gray;
}
```

### 16.4 一个组件的完整示例 `assets/js/components/compare.js`

```js
import { esc, accentOf } from '../core/dom.js';

function side(s) {
  const a = accentOf(s.accent);
  return `
    <div class="rounded-xl border ${a.border} ${a.bg} p-5">
      <h3 class="text-base font-medium ${a.text}">${esc(s.title)}</h3>
      ${s.points?.length ? `<ul class="mt-3 space-y-2 text-sm text-gray-700 leading-relaxed">
        ${s.points.map(p => `<li class="flex gap-2">
          <span class="${a.text} select-none">·</span><span>${esc(p)}</span></li>`).join('')}
      </ul>` : ''}
      ${s.examples?.length ? `<div class="mt-4 flex flex-wrap gap-2">
        ${s.examples.map(e => `<span class="ui-badge border ${a.border} ${a.bg} ${a.text}">${esc(e)}</span>`).join('')}
      </div>` : ''}
    </div>`;
}

function diff(d) {
  if (!d) return '';
  return `
    <div class="mt-4 overflow-x-auto rounded-xl border border-gray-200">
      <table class="ui-table">
        <caption class="sr-only">${esc(d.caption || '差异对照')}</caption>
        <thead><tr>
          ${d.columns.map(c => `<th class="ui-th">${esc(c)}</th>`).join('')}
        </tr></thead>
        <tbody>
          ${d.rows.map(r => `<tr>
            <td class="ui-td text-gray-500">${esc(r.k)}</td>
            <td class="ui-td">${esc(r.l)}</td>
            <td class="ui-td font-medium">${esc(r.r)}</td>
          </tr>`).join('')}
        </tbody>
      </table>
    </div>`;
}

export default function compare(section) {
  return `
    ${section.title ? `<h2 class="text-xl font-semibold text-gray-900 mb-2">${esc(section.title)}</h2>` : ''}
    ${section.lead ? `<p class="text-sm text-gray-500 mb-5">${esc(section.lead)}</p>` : ''}
    <div class="grid gap-4 md:grid-cols-2">
      ${side(section.left)}${side(section.right)}
    </div>
    ${diff(section.diffTable)}
  `;
}
```
